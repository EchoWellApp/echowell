## Hard rules for every step

| Rule | Source |
|---|---|
| The interim Netlify / Railway / Neon stack holds synthetic and test data only, in every environment including the one named `production`. No real resident data is ever loaded, ingested, entered or connected there. | AGT-014, SEC-001, DEP-008, TPS-002, VIS-024, D-28, D-OWNER-4 |
| EchoWell goes live with real resident data only on AWS, after budget approval, the BAA and the sign-off of section N. Interim API keys are never issued to devices deployed at Edgewood. | DEP-118, TPS-003, SEC-002, SEC-003, VIS-027 |
| `PIPELINE_PROFILE=test_v0_1` and `PIPELINE_AS_OF` are never set in production; the backend refuses to start if they are. Production is never seeded. | AGT-015, ENV-010, ENV-012, DEP-007, DEP-070 |
| The answer key is loaded into `evaluation_ground_truth` only where the profile is `test_v0_1` (local, CI, staging); no pipeline stage reads it. | D-38, VIS-030, AGT-007 |
| Schema changes reach staging and production only through the Railway pre-deploy command `alembic upgrade head`; no manual DDL, no migration from a GitHub workflow, no `alembic downgrade` in production. | DEP-040, DEP-060, DEP-086, CIC-003, D-58 |
| Secrets live only in Railway variables, the five GitHub `staging` environment secrets, the two deploy tokens of the GitHub `production` environment and (AWS) Secrets Manager; never in a committed file, an issue, a PR or a log. | ENV-005, DEP-033, CIC-090, AGT-016, GIT-073 |
| The repository has only `main` and feature branches; PRs target `main`. Every merge to `main` deploys staging automatically; production changes only through an approved manual run of `deploy-production.yml` for a chosen `main` commit. | D-99, GIT-012, GIT-013, DEP-002, DEP-003, DEP-004 |
